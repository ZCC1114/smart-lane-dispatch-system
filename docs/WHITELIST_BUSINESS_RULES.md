# 白名单管理业务规则

## 背景

白名单用于控制总入口车辆是否允许参与蓄车池车道分配。该功能只影响总入口摄像机识别后的分配链路，不改变车道入口摄像机、出口地感、手动调度和完成保障的既有逻辑。

## 数据维护

- 左侧菜单新增「白名单管理」。
- 管理员可以通过 Excel 导入白名单车牌。
- 当前导入模板按第一张工作表的第一列读取车牌号；首个非空单元格包含「车牌」时按表头跳过。
- 导入时会规范化车牌号：去掉中点、去掉空白并转为大写。
- 白名单车牌在数据库中唯一。
- 重复导入同一车牌时不新增记录，只更新「更新时间」和「更新人」。
- 白名单列表展示车牌号、创建时间、更新时间、创建人和更新人。

## 导入效率

- 后端按批次读取和写入，避免几万条车牌逐条查询。
- 数据库对白名单车牌建立唯一索引 `uk_whitelist_plate`，保证精确匹配效率。
- 现场 Redis 可用时，后端会把白名单车牌加载到 Redis Set。
- 总入口判断时优先使用 Redis `SISMEMBER`；Redis 不可用或缓存异常时，自动退回数据库索引查询。
- 每次白名单导入完成后会刷新 Redis 白名单缓存。

## 启用开关

- 新增「白名单过滤」开关，默认关闭。
- 开关关闭时，总入口车辆沿用原有分配逻辑。
- 开关开启时，总入口车辆必须命中白名单后才继续参与车道分配。
- 白名单为空且开关开启时，所有总入口车辆都会按非白名单处理。

## 总入口处理规则

1. 总入口摄像机识别到车牌后，先执行原有车牌规则。
2. 蓝牌且第 4 位不是 `T` 的车辆仍按原逻辑忽略，不参与分配。
3. 白名单过滤关闭时，不做白名单判断。
4. 白名单过滤开启时：
   - 命中白名单：继续执行原有总入口车道分配逻辑。
   - 未命中白名单：生成非白名单告警，不参与车道分配。

## 告警规则

- 非白名单车辆生成独立告警类型 `not_whitelisted`。
- 告警内容为「非白名单车辆，总入口识别后已禁止参与车道分配」。
- 车辆告警列表中展示为「非白名单」。
- 大屏左侧告警区暂归入「其他」区域展示。
- 如果同一车辆同时命中黑名单和非白名单条件，车辆告警优先展示黑名单告警，避免同一事件重复展示为两种风险类型。

## 后续可调整点

- Excel 模板确定后，可以扩展车牌列识别和导入字段。
- 如果需要单条新增、删除或禁用白名单记录，可以在现有白名单表上补管理操作。
- 如果现场希望非白名单车辆触发语音或诱导屏提示，可以在总入口拦截节点增加设备下发动作。
