## 低危整改结果

- 移除业务代码中的临时线程和无界执行器，改为有界、可关闭的托管线程池。
- 将设备通信、LED SDK 和 MQTT 的宽泛异常处理收窄到明确异常类型；MQTT 消息监听器在分发边界隔离单条消息的运行时异常，避免一条异常报文中断共享连接；对外返回通用错误，底层异常只记录到服务日志。
- JWT 增加密钥长度、有效期和 Token 长度校验，并使用常量时间比较签名。
- LED 测试接口只允许连接服务端已配置的主机、端口、控制卡代际和型号，避免被用于内网探测。
- 匿名大屏接口不再暴露操作人、来源、备注和设备内部字段。

## 无法仅靠代码彻底消除的残余项

1. MQTT、TCP DIDO 和 LED 厂商 SDK 当前使用设备支持的明文 TCP 协议。只有在 Broker 和现场设备支持 TLS 后，才能完成传输加密；本次未改服务器和设备协议。
2. `deploy/mosquitto/password_file` 是 Broker 侧密码哈希文件。仓库已不再公开对应明文默认口令，但上线前仍须在部署环境重新生成该文件并轮换 MQTT 凭据；本次未操作 Broker。
3. Spring Security 配置方法的 `throws Exception`、厂商 SDK 适配器的单点 `catch (Exception)`、定时任务及 MQTT 消息分发边界的 `catch (RuntimeException)` 属于框架、第三方接口或异步边界。异常已被集中转换/记录，不会向 HTTP 客户端泄露。
4. 测试代码中 MockMvc/JUnit 方法的 `throws Exception` 不进入生产运行包，属于测试接口约定，不作为生产漏洞整改。

## 上线前必填配置

- `APP_JWT_SECRET`：使用高强度随机值，至少 32 个字符。
- `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD` 及应用数据源账号密码。
- `COMPOSE_NETWORK_SUBNET`、`COMPOSE_NETWORK_GATEWAY`：选择与现场网络不冲突的私网网段。
- 如需初始管理员，临时启用 `APP_BOOTSTRAP_ADMIN_ENABLED` 并设置独立随机口令；创建成功后关闭该开关。
- 使用 MQTT 或现场硬件时，显式填写对应主机、端口和凭据，并重新生成 Mosquitto 密码文件。

不得把真实密钥、口令或现场地址提交到仓库。上述值应通过部署环境、密钥管理系统或仅存在于服务器的环境文件注入。
